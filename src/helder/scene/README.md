# helder.scene

A scene layer for 3D games on `helder.gfx`, in pure Haxe (Haxe package
`helder.scene`; what comes next: the [roadmap](/README.md)). It is ordinary
gfx code: use the parts you want, replace the rest.

These pages go from the scene graph to what draws it:

- [World and nodes](#world-and-nodes): the scene graph, cameras, the fixed step;
- [glTF and models](#gltf-and-models): files typed when compiling, packed for
  run time, animated;
- [Materials](#materials), [Lights and shadows](#lights-and-shadows), [Fog](#fog),
  [HDR and post-processing](#hdr-and-post-processing) and [Post effects](#post-effects-and-the-view-buffers) (AO,
  depth of field, outlines, FXAA, a LUT): the renderer;
- [Instancing](#instancing) and [GPU particles](#gpu-particles): many
  things in few draws;
- [Lines](#lines), [Text in the world](#text-in-the-world) and
  [Picking](#picking): lines with a width, text as geometry, rays cast
  at triangles;
- [`<Scene>` markup](/src/helder/scene/view/README.md): the scene in helder.view's markup, inside a
  ui;
- [Input](#input), [Debugging](#debugging) and
  [TypeScript](#typescript).

On the docs site each page's examples run in the page (WebAssembly, on
WebGPU or WebGL2): press Play. Their source is the file shown beside
them, built and tested with the rest of the repository; `helder run
<file>` runs one natively.

## Renderer design

Nodes are handles into flat stores, with cameras, lights and renderers
as components. The forward renderer sorts and instances its draws.
Opt-in render features and material factories link their shaders only
when a program uses them. Slot materials compile at build time for
each pass that needs them.

GL ES 3.0 and WebGL2 are the portable floor. Where the device has
[compute](../gfx/README.md#compute), the renderer can use storage
buffers, indirect draws and compute stages for work such as clustered
lights and particles. Portable paths use render passes or CPU work.
Frame paths reuse lists and buffers, and queries such as picking write
into results the caller owns.

## World and nodes

A `World` is a scene graph of `Node`s: handles (an `Int`: the world, a
generation, a slot) over flat arrays of transforms, so nodes cost no
object each and a disposed node's handle is stale (`valid` false).

```haxe
var world = new World();
var arm = world.node("arm");                 // under world.root
arm.position = new Vec3(2, 0, 0);            // Vec3 and Quat: immutable values
arm.rotation = Quat.axisAngle(new Vec3(0, 0, 1), Math.PI / 2);
var hand = world.node("hand", arm);
var eye = world.node("eye");
var camera = Camera.attach(eye, Camera.perspective(Math.PI / 3, 0.1, 100));
eye.position = new Vec3(4, 3, 6);
eye.lookAt(new Vec3(0, 1, 0));
var mvp = camera.viewProjection(width / height) * hand.worldMatrix();
```

A node's transform is its parent's times its own: turn a pivot and
everything under it turns. Here a planet's orbit is a pivot at the sun,
its moon's a pivot under the planet, and the camera a node of its own:

Example: [World and nodes](/docs/examples/scene-nodes/Nodes.hx) (`helder run docs/examples/scene-nodes/Nodes.hx`).

A node's `worldMatrix()` is cached until a transform above it changes.

### Stores

What nodes carry is in typed stores (`world.store(kind)`, a `StoreKind`
per kind: `Camera.KIND`, `MeshRenderer.KIND`, `Light.KIND`), made when
first used. `MeshRenderer.attach(node, mesh)`, `Light.attach(node, light)`
and `Camera.attach(node, camera)` put one on a node.

### Time

`FixedStep` runs a simulation at a fixed rate from the app loop's frames
and gives the fraction between the last two steps; `Stages` runs a frame's
work in ordered stages (`Input`, `FixedUpdate`, `Update`, `LateUpdate`,
`PreRender`).

### Fast refresh

`HotWorld.keep(world, key)`, after the world is made: under `helder dev`
the old build's transforms are put back by node path; nothing without
`-D hxmc.dev`.

## glTF and models

### glTF

`Gltf.parse(bytes, ?resolve)` reads glTF 2.0, .gltf (buffers as `data:`
URIs or files `resolve` returns) and .glb, into a `GltfDoc`: typed and
checked data (indices in range, views inside buffers, accessors inside
views). `doc.floats(accessor)` and `doc.indices(accessor)` read accessors of
any component type, normalized or strided. Materials' extensions:
KHR_texture_transform (one transform for a material's maps, or each map
its own with TEXCOORD_1: `Material.textureTransforms`),
KHR_materials_emissive_strength, KHR_materials_clearcoat,
_transmission, _volume, _ior, _specular, _sheen, _iridescence and
_anisotropy with their maps ([Materials](#the-gltf-material-extensions));
alphaMode MASK is cut out at alphaCutoff. `GltfNodes.build(doc, world, ?parent, ?scene, ?mesh)` makes the node
hierarchy (TRS or matrices, cameras); `GltfScene` makes the GPU meshes and
materials once and `instantiate(world)` copies the hierarchy into a world.
helder.asset's `Asset.embed(path)` builds a file into the code itself.

### Models

```haxe
var hero = Model.of("models/hero.glb");      // checked and typed when compiling
var root = hero.instantiate(world, device);  // GPU meshes made once, shared
var hand = root.find(hero.nodes.LeftHand);   // hero.nodes.LeftHnad: a compile error
```

`Model.of` reads the file's names when compiling (nodes, meshes,
materials, animations: `model.nodes`, ...). Its path is an asset's
([helder.asset](/src/helder/asset/README.md)): found under a class path or
the project, checked when compiling, the file in every build that still
uses it (the executable's data, the APK's or the app's `assets/`, beside
the page), read before anything runs (in the browser fetched before main:
`browser.mjs`'s `assets` option, `<module>.assets.json`). For now
self-contained files only (one embedded buffer, images inside it).
Textures need a decoder, named by the program so that none is linked
otherwise (`helder.image`'s; a glTF viewer natively: 805 KB without one,
1.1 MB with PNG, JPEG and WebP):

```haxe
Images.decode = Images.png;     // PNG only
Images.decode = Images.common;  // PNG, JPEG and WebP
```

A model referenced with `Model.of`, its nodes and its animation typed from
the file, under a sun with a shadow map:

Example: [glTF scene](/examples/gltf-viewer/GltfViewer.hx) (`helder run examples/gltf-viewer/GltfViewer.hx`).

### The asset step

```sh
haxe -cp src \
  --run helder.scene.gltf.Pack level.glb level.hxm3d
```

```haxe
PackedModel.read(Asset.embed("level.hxm3d"), device).instantiate(world);
```

A packed model needs no glTF reader or JSON at run time (73 KB less
natively, `tests/3d/size/sizes.sh`): meshes (vertices in the renderer's layout,
joints and weights, tangents computed at build time for normal maps),
materials (factors, maps, sampler, the extensions' fields), images (decoded by `Images.decode`
when loaded), cameras, lights, skins, morph targets, animations (`model.clip(name)`,
playing on the nodes `instantiate` made) and the hierarchy.

`--textures bc` or `--textures astc` compresses the images for a target's
GPUs (BC1, BC3 with alpha: desktops and the web; ASTC 4x4: phones), their
mip chains made at build time (helder.image's `BlockCompress`):
`PackedModel` uploads the levels as they are (`Images.compressed`), or on a
GPU without the format (`Device.supports`) decodes them on the CPU.
Sponza's 69 textures: 363 MB on the GPU as RGBA8, 50 MB as BC, 95 MB as
ASTC ([examples/sponza](/examples/sponza)). Built natively, the step packs
them in seconds.

### Loading in the background

Big files or loading screens: `Asset.model(path)` (or `Model.of(path,
Lazy)`) is an `Asset` of the same typed model, loaded in the background
(`var hero = Asset.model(path).load();` in a coroutine; `asset.ready`,
`asset.peek()` in the frame loop); under `helder dev` a change to the file
is loaded again into the same `Model` (`replace`: each mesh's primitives
and materials swapped in the mesh objects its instances draw; their nodes,
morphs and skins as they were made). `Model.load(path)` loads a path known
only at run time (not bundled). Loads advance on the main thread's loop
(`App.run`), or in `Assets.poll()`, which `Stages.frame` calls.

### Animation

```haxe
var made = [];
var root = hero.instantiate(world, device, null, made);   // made: the glTF nodes by index
var animator = new Animator(made);
animator.play(hero.clip(hero.animations.Run), {loop: true, fade: 0.2});
// each simulation step:
animator.update(dt);
```

Clips are glTF's keyframes (translation, rotation, scale; step, linear,
cubic spline). Skinned glTF meshes deform with their joints (a `Skin` per
instance, joint matrices in a texture: `renderer.use(new
Skinning(device))`); `tests/3d/skinned.glb` is a generated two-joint
sample.

## Geometry

### Shapes made in code

Shapes are made in code on the CPU, three.js's geometries by name, their
parameters three's names and defaults (option structures, each field
optional), their vertex and index counts three's for the same parameters:

```haxe
var rail = Geometry.cylinder({radiusTop: 0.2, radiusBottom: 0.2, height: 1, radialSegments: 8, flat: true});
var post = Shapes.of(device, rail, wood);    // the upload: a Mesh of one primitive
var knot = Geometry.torusKnot({radius: 0.5, tube: 0.15, p: 2, q: 3});
var vase = Geometry.lathe([new Vec2(0.2, 0), new Vec2(0.4, 0.5), new Vec2(0.15, 1)], {segments: 24});
var hose = Geometry.tube(Curve3.catmullRom(points), {radius: 0.05, tubularSegments: 96});
```

`Geometry.box`, `sphere`, `cylinder`, `cone`, `capsule`, `torus`,
`torusKnot`, `ring`, `circle`, `plane`, `lathe(points, ...)` and
`tube(curve, ...)` return a `VertexData`, free of the GPU: tested on Eval,
read by physics, packable. Like three's: y up, the plane, circle and ring
in xy facing +z, the torus about z, a cylinder's seam at +z; unlike
three's, uvs run down the image (v flipped) as glTF's do and every helder
material reads them. Every generator also takes `flat: true` (its vertices
unshared, each triangle its face's normal: the low-poly look) and
`tangents: true` (for normal maps).

A `VertexData` is read with `position(i)`, `normal(i)`, `uv(i)`,
`index(k)`, `vertexCount` and `count`, and moved into another with
`transformed(m)`, `rotated(x, y, z)` and `translated(x, y, z)` (three's
`applyMatrix4`; a mirror keeps the winding). `Shapes.of(device, geometry,
material)` uploads one; `Shapes.box`, `sphere`, `capsule` and `plane` are
the common ones at their usual sizes (`Shapes.plane` is `Geometry.plane`
turned to face up). In markup a geometry is a tag: `<cylinderGeometry
radiusTop={0.2} height={1}/>` ([`<Scene>` markup](/src/helder/scene/view/README.md)).

Each column here is a generator, each row a shading model
([Materials](#materials)):

Example: [Primitives](/examples/primitives/Primitives.hx) (`helder run examples/primitives/Primitives.hx`).

### Curves

`Curve3` is a curve in space, an immutable value (three's `Curve`):
`Curve3.bezier(a, b, c, d)`, `catmullRom(points, closed, tension)`,
`line(a, b)` and `path(curves)`, read by a parameter (`point(t)`,
`tangent(t)`) or by a distance along it (`pointAt(d)`, `tangentAt(d)`:
its `length` tabulated once, when made), and `frames(n, closed)`: n + 1
frames at equal lengths that turn as little as they can (parallel
transport, so no flip where the curve bends back), for a tube's rings or
a camera on rails.

Tests: `src/helder/scene/render/Geometry.test.hx` (three's counts, closed
shapes closed and wound one way round, normals unit, uvs 0 to 1, flat, the
transforms), `src/helder/scene/math/Curve3.test.hx` (lengths, frames
without flips); the 3d lane's `primitives` frame (every generator, smooth
with its normals as colours, flat in Lambert's light; its TypeScript twin
the same frame).

## Materials

### The renderer

```haxe
var renderer = new Renderer(device);
new GltfScene(Gltf.parse(Asset.embed("sample.glb")), device).instantiate(world);
// in the frame:
renderer.draw(enc, world, camera);   // one pass into the frame
```

The renderer extracts the world's meshes (`MeshRenderer`) into a draw
list (shown nodes inside the view, sorted by pipeline and material), then
records it with `PbrShader`: glTF's metallic-roughness model, the world's
lights ([Lights and shadows](#lights-and-shadows)), a sky-and-ground ambient, ACES
tone mapping, sRGB output (or linear light into HDR targets:
[HDR and post-processing](#hdr-and-post-processing)). Nodes drawing the same primitive are
drawn in one instanced call (`renderer.instancing`, on by default:
[Instancing](#instancing)). Programs draw at injection points:
`renderer.inject(BeforeOpaque | AfterOpaque | AfterPass, (enc, frame) -> ...)`;
features reach the renderer through `RenderFeature` (`renderer.use(...)`),
so unused ones are not linked. Shapes are made in code with `Geometry`
and `Shapes` ([Geometry](#geometry)).

A frame records, in order: the shadow maps, the view buffers' prepass
(when an effect or the program asks for them: [Post effects](#post-effects-and-the-view-buffers)),
the screen's ambient occlusion (`post.ao`), the main pass, the
`AfterPass` hooks; then post. With no GPU (`-D helder.soft`, `helder run
--headless --soft`) all of it draws on helder.gfx's CPU back end, compute
paths on their fallbacks: tests/3d's scenes are the GPUs' goldens within
their tolerance (two within 6 levels: helder.gfx's README, On the CPU), the
same bytes on every machine. Nothing is allocated per frame: the blocks
the renderer writes are kept and their fields set (a struct literal per
write would allocate on hxmc), and each uniform block's writer is a class
of its own (helder.gfx's `UniformWriter`: no closure).

### The standard material

```haxe
var gold = new Material("gold", new Vec4(1, 0.78, 0.34, 1), 1, 0.2);   // base colour, metallic, roughness
var lamp = new Material("lamp", new Vec4(0, 0, 0, 1), 0, 1, new Vec3(2.5, 1.6, 0.5));   // emissive: linear light
MeshRenderer.attach(world.node("ball"), Shapes.sphere(device, gold, 0.5));
```

A base colour (and its map), metallic and roughness (and theirs),
emission, an occlusion map and a normal map (with
`renderer.use(new NormalMaps(device))`, made before the models load: they
get tangents, the file's or computed). See-through materials
(`material.blend`, glTF's alphaMode BLEND) are drawn after the opaque
ones, farthest first. Materials also take a uv transform (`uvOffset`,
`uvRotation`, `uvScale`), an alpha cutoff (`alphaCutoff`: below it
dropped), a clear coat (`clearcoat`, `clearcoatRoughness`: a polished
dielectric layer, its reflection of the sun and the environment over the
base) and transmission (`transmission`: a thin surface, drawn see-through
twice: what is behind multiplied by its colour, then its reflections over
it). The rest of glTF's material extensions are the physical shaders',
below.

Example: [Materials](/docs/examples/scene-materials/Materials.hx) (`helder run docs/examples/scene-materials/Materials.hx`).

### The glTF material extensions

glTF's material extensions are `Material`'s fields, with glTF's names:

| Extension | Fields |
|---|---|
| KHR_materials_sheen | `sheenColor`, `sheenRoughness`, `sheenColorTexture`, `sheenRoughnessTexture` |
| KHR_materials_specular, _ior | `specularFactor`, `specularColor`, `specularTexture`, `specularColorTexture`, `ior` |
| KHR_materials_clearcoat | `clearcoat`, `clearcoatRoughness`, `clearcoatTexture`, `clearcoatRoughnessTexture`, `clearcoatNormalTexture`, `clearcoatNormalScale` |
| KHR_materials_transmission, _volume | `transmission`, `transmissionTexture`, `thickness`, `thicknessTexture`, `attenuationColor`, `attenuationDistance` |
| KHR_materials_iridescence | `iridescence`, `iridescenceIor`, `iridescenceThicknessMinimum`, `iridescenceThicknessMaximum`, `iridescenceTexture`, `iridescenceThicknessTexture` |
| KHR_materials_anisotropy | `anisotropy`, `anisotropyRotation`, `anisotropyTexture` |
| TEXCOORD_1, a transform a map | `textureTransforms` (a `UvTransform` each for the base colour, metallic-roughness, normal, occlusion and emissive maps) |

They are build-time options of `pbr` (`sheen`, `specular`, `clearcoat`,
`transmission`, `iridescence`, `anisotropy`, `uvSets`), not a shader
made at run time: a variant with one fills that layer of the surface
(`LitSurface`'s optional fields) between the surface's slots and the
lights, and its `direct` and `indirect` slots are the physical ones
(`physicalDirect`, `physicalIndirect`): Charlie's sheen, the specular
layer's f0 and f90, a clear coat with its own normal and roughness,
Belcour and Barla's thin film, anisotropic GGX with a bent reflection,
refraction through a volume with Beer's absorption. A layer a variant does
not fill reads as nothing and its code folds away (helder.gfx's `Prune`):
a variant without sheen has no sheen in its text. `PhysicalShader.of({sheen:
true, clearcoat: true})` is the `MaterialShader` of a set, each set
compiled once a build, linked only where it is named.

Which sets a game has comes from its models: `Model.of` reads each
material's extensions when compiling and names the sets they use, so a
game whose models have no sheen links no sheen. Materials made in code, and
models loaded at run time (`Model.load`, whose files are not known when
compiling), are drawn by `Physical`, the set with every extension, opted
in (one large shader):

```haxe
renderer.use(new Physical());                 // materials whose fields use an extension
renderer.use(new Transmission(device));       // the opaque frame behind see-through ones
```

Example: [glTF material extensions](/docs/examples/scene-physical/Extensions.hx) (`helder run docs/examples/scene-physical/Extensions.hx`).

`Transmission` copies the opaque frame (with its mips) once a frame that
has a transmitting surface in view, after the opaque surfaces and the sky:
the frame's pass is split there, the copy read through the surface at the
point its refracted view leaves it, at the mip level of its roughness. It
needs the frame in a texture (an offscreen renderer: a `<Scene>`'s box,
`drawInto`); without it a transmitting surface shows the environment
refracted through it. A material's extension maps are read from up to two
images (glTF's channels: sheen's colour and roughness in one, the coat's
factor and roughness...: helder.gfx's 16 slots a shader).

Costs, at the renderer's level (`tests/3d/size/sizes.sh`'s phase 6 rows, a
glTF model drawn, `-dce full`), what each adds when a material uses it,
its variants' shader text most of it:

| Used | Linux x86-64 | wasm32 |
|---|---|---|
| none (the renderer, against main before phase 6) | +5.5 KB | -4.8 KB |
| sheen | +228 KB | +343 KB |
| specular (and ior) | +224 KB | +335 KB |
| clearcoat | +228 KB | +341 KB |
| transmission (and volume) | +228 KB | +347 KB |
| iridescence | +236 KB | +358 KB |
| anisotropy | +228 KB | +346 KB |
| uvSets (TEXCOORD_1) | +253 KB | +375 KB |
| `Physical` (every one) | +303 KB | +492 KB |
| `Transmission` | +23 KB | +22 KB |

Unused, the extensions add the larger material block alone (its fields
in each variant's text): their reading and binding are linked by
`Physical` and `Model.of`'s sets only (helder.gfx's writers, shorter with
this change, make up for it as wasm32).

Against Khronos' sample viewer: [examples/gltf-showcase](/examples/gltf-showcase/README.md).

### A material of its own

The standard material is a slot object, `pbr` (`PbrShader`; helder.gfx's
`slots`, [README.md](/src/helder/compiler/README.md) 3): one shader whose
variants are the renderer's (`pbr.variant({normalMap, skinned,
instanced, prepass})`: `PbrShader`, `PbrNormalShader`, `PbrSkinnedShader`,
`PbrInstancedShader`, `PbrInstancedNormalShader`; the view buffers'
`PbrPrepassShader`, `PbrPrepassInstancedShader`, `PbrPrepassSkinnedShader`;
the shadow map's casters are `shadowCaster`'s) and whose slots a material replaces: `color`,
`alpha`, `normal`, `roughness`, `metalness` and `emissive` (of the
fragment's `PbrSurface`), `position` (of the vertex's `PbrPoint`), and
how light reaches the surface: `direct(s, l, p)`, the light one source
adds (the sun's, each point or spot light's; `l` a `LightSample`: its
`color` times its attenuation, its `shadow`, the two multiplied as
`radiance`, its `direction`, `ndotl`), and `indirect(s, env, p)`, the
ambient and the reflections (`env` an `IndirectLight`: `irradiance` along
the normal, `radiance` along the reflection, `occlusion`), each of the
surface with the other slots' results (`s` a `LitSurface`: `albedo`,
`alpha`, `metalness`, `roughness`, `normal`, `view`, `world`, `uv`, `up`).
A slot takes as many inputs as the slot object's type gives it before its
parameters. `MaterialShader.material(pbr.with({...}))` compiles them, at
build time, into a shader of the material's own (`material.shader`, every
variant the renderer draws with, for the GPU only: no CPU twin of its
stages is linked); a slot's parameters beyond the standard ones are
blocks of its own (`material.uniforms`, written by its `params`). Here the
emissive and colour slots are replaced:

Example: [Glow](/examples/glow/Glow.hx) (`helder run examples/glow/Glow.hx`).

### Shading models

A shading model is a material's shader, made by `Material`'s factories,
three.js's materials by name:

```haxe
var grass = Material.toon({color: new Vec4(0.4, 0.8, 0.3, 1), steps: 3, shade: new Vec3(0.35, 0.4, 0.6)});
var sign  = Material.unlit({color: new Vec4(1, 0.9, 0.2, 1), texture: signImage});
var clay  = Material.matcap({matcap: clayImage});   // the normal in view space reads the sphere's picture
var debug = Material.normals();                     // MeshNormalMaterial; Material.depth(near, far): MeshDepthMaterial
var lam   = Material.lambert({color: c});           // 1 dot a light, no GGX: the cheap lit one for phones
var shiny = Material.phong({color: c, shininess: 60});
var std   = Material.standard({color: c, roughness: 0.4});   // pbr, as new Material(...)
```

| Factory | three.js | How | Per pixel, per light |
|---|---|---|---|
| `unlit` | `MeshBasicMaterial` | the colour times its texture, fogged | none |
| `matcap` | `MeshMatcapMaterial` | a lit sphere's picture (`matcap`, kept as the `emissiveTexture`) by the normal as the eye sees it | none (1 texture read) |
| `normals` | `MeshNormalMaterial` | the normal in view space as a colour | none |
| `depth(near, far)` | `MeshDepthMaterial` | the depth along the view, white at near, black at far (linear) | none |
| `lambert` | `MeshLambertMaterial` | each light's diffuse, the ambient's diffuse, no highlight | 1 dot |
| `toon` | `MeshToonMaterial` | each light's n.l times its shadow in `steps` bands, the side away from every light the albedo times `shade` | 1 dot and a step |
| `phong` | `MeshPhongMaterial` | Lambert's diffuse and a Blinn-Phong highlight (three's `shininess`, kept as the roughness of the same lobe), pbr's reflections | a pow |
| `standard` | `MeshStandardMaterial` | pbr: GGX, Smith and Schlick | GGX, Smith and Schlick |

The lit ones are `pbr` with `direct` and `indirect` replaced
(`helder.scene.render.shading`: `lambert`, `toon`, `phong`), so they keep
the shadows, the point and spot lights, the fog, normal maps, instancing
and skinning; toon's bands are per light, its shadow banded with it. The
unlit ones are a slot object of their own, `unlit` (its slots `color`,
`alpha`, `position`; its variants plain, skinned and instanced, no normal
map), which sums no light and reads no shadow map; `matcap`, `normals` and
`depth` are `unlit.with({color: ...})`. A material of one's own on any of
them is `MaterialShader.material(toon.with({...}))`. `material.toneMapped`
(three's) false shows a colour as it is, only encoded for an 8-bit target
(`normals` and `depth` by default).

Each factory references its own shader alone: a program that never calls
`Material.toon` links none of toon's. Unused, they cost the renderer 39 KB
natively and as wasm32 (its shader's text, the slots' structure); a lit
model, when used, costs its five variants' shader text, about 230 KB
natively (HLSL) and 300 KB as wasm32 (GLSL and WGSL)
(`tests/3d/size/sizes.sh`). Each row here is a model, each column a shape:

## Lights and shadows

### Lights

```haxe
var sun = world.node("sun");
Light.attach(sun, Light.directional(new Vec3(1, 0.95, 0.85), 2.2));   // colour, intensity
sun.lookAt(new Vec3(0.35, -0.45, 0.82));                              // it shines along its node's -z
Light.attach(world.node("lamp"), Light.pointLight(new Vec3(1, 0.3, 0.1), 3, 4));   // and a range, metres
Light.attach(world.node("spot"), Light.spot(color, 6, 10, 0.15, 0.3));            // inner and outer cones, radians
Light.attach(world.node("sky"), Light.hemisphere(skyColor, groundColor, 1));     // three's HemisphereLight
```

The standard material is lit by the world's first directional `Light`
(a world without lights: `renderer.sun*`), its point and spot lights, and
a sky-and-ground ambient: the world's first hemisphere light
(`Light.hemisphere(sky, ground, intensity)`: the sky's colour from above,
the ground's from below, blended by the normal), else `renderer.sky` and
`renderer.ground`. A light's `kind` is `Directional`, `Point`, `Spot` or
`Hemisphere` (`light.local`: a point or a spot light); tests/3d's
`hemisphere` frame is lit by a hemisphere light alone. `renderer.rim` (a
colour times intensity) and `rimPower` add a rim light from the sun's side
along the silhouettes. `material.emissiveNight` (0 to 1) keeps a
material's light to its night side, faded in across the terminator (a
planet's city lights).

### Many lights

Each frame the renderer gathers the world's point and spot lights whose
reach (a sphere of their `range`) meets the view, the most important
first (the brightest over their distance past their range), at most 32:
the frame's lights (`renderer.frameLights`, rows of one small RGBA32F
texture with the shadow tiles after them, written once a frame: indexing a
uniform block by a light's row cost Metal four times the frame on iOS's
simulator). Each
draw is lit by the eight of them that reach its bounds most, listed by the
renderer as it extracts the draw (Godot Mobile's and Unity's per-object
lights): a lamp lights the objects it reaches, a far one costs them
nothing, and a pixel never loops over more than eight. Nodes of one mesh
are still one instanced draw when their lists are the same (the lists
are by light, so the same lights make the same list); a floor of tiles
gets a list a tile (tests/3d's `lights8` frame: 32 lights over 64 tiles
and a pillar twelve of them reach, its eight brightest lighting it).

One large surface under many lights wants more than eight:
`ClusteredLights` (Forward+) cuts the view into cells (16 x 9 tiles, 24
slices of depth growing away from the camera), lists the lights reaching
each (at most `maxPerCell`, 32), and lights each pixel by its cell's,
from up to `maxLights` (256) a frame:

Example: [Many lights](/docs/examples/scene-clustered/ManyLights.hx) (`helder run docs/examples/scene-clustered/ManyLights.hx`).

The lists are made by a compute pass where the device has one (WebGPU,
Metal, D3D11, GL ES 3.1: an invocation a cell, every light tested), else
on the CPU (WebGL2, GL ES 3.0: each light tested against the cells its
sphere's box touches), the same test in the same order, so both paths draw
the same frame (tests/3d's `clustered` frame is drawn by both, against one
golden, and is its brute force's: every light at every pixel). The lists
and the lights go into one R32F texture the standard material reads in a
branch, so no material has a variant more and it runs on WebGL2.

Measured (`tests/bench/LightBench.hx`, headless at a phone's render size,
810 x 1800, on Mesa's llvmpipe; a CPU's rasterizer is not a phone's GPU,
the ratios are what carry over; a floor and nine pillars, 24.5 ms with no
local light):

| 128 point lights | Frame | Against none |
|---|---|---|
| each draw's eight (the floor lit by eight of them) | 47.6 ms | 1.95x |
| `ClusteredLights`, its cells on the GPU | 74.2 ms | 3.03x |
| `ClusteredLights`, its cells on the CPU (0.37 ms of it) | 71.4 ms | 2.92x |
| every light at every pixel (one cell) | 324 ms | 13.3x |

Each draw's eight cost what eight lights cost a pixel; clustered, a pixel
pays for its cell's lights alone (here up to a dozen, the floor lit by all
of them), a quarter of the brute force's. The CPU's cells for 256 lights
take 0.6 ms (`Clusters.test.hx`, natively). What it adds to a program:
66 KB natively, 61 KB as wasm32 (`tests/3d/size/sizes.sh`), nothing
unused; the renderer's lists and the frame's lights are the renderer's
own.

### Shadows

Shadows are opted in: `renderer.use(new Shadows(device))`. `Shadows` is
one atlas (an R32F texture and its depth buffer) of tiles: the sun's and
its cascades, and the point and spot lights' that cast.

**The sun.** The world's first directional light casts (its
`castShadows`, true by default; the renderer's sun in a world without
lights): one map of `size` texels fitted to the casters, filtered 3x3;
`Shadows.cascaded(device, size, split)`: two cascades, the first sharp
over the camera's view up to `split` metres. A primitive's casters are one
instanced draw a tile.

Softer shadows are opted in with `.soft(radius, samples, spread)`: a disc
of `samples` taps (8 for phones, 16, 32) out to `radius` metres, turned
per texel; with a `spread` a blocker search first (half as many taps), the
penumbra widening by `spread` a metre from its caster up to the radius,
so a shadow is sharp where it meets what casts it (PCSS); `spread` 0, the
radius everywhere. Each tap is compared with the surface's own depth there
(its plane as the light sees it), so a far smaller `bias` than the 3x3
filter's keeps tilted surfaces from shadowing themselves, and low casters
(a rail on a green) still cast: Little Skies (helder/little-skies) uses
`new Shadows(device, 2048).soft(0.15, 12, 0.08)` with `bias = 0.001`, its
sun's map the whole atlas (tests/3d's `softshadows` frame; `shadows` and
`cascades` keep the 3x3 filter).

Example: [Lights and shadows](/docs/examples/scene-lights/Lights.hx) (`helder run docs/examples/scene-lights/Lights.hx`).

**Point and spot lights** cast when asked, `light.castShadows = true`
(three.js's `castShadow`), each with its own `light.shadow`:

Example: [Spot and point shadows](/docs/examples/scene-shadows/SpotAndPoint.hx) (`helder run docs/examples/scene-shadows/SpotAndPoint.hx`).

The first local light to cast makes the atlas wider by a square of
`atlas` texels (1024: `new Shadows(device, size, {atlas: 1024, maxLocal:
4, tileSize: 512})`), where a spot light gets one tile of its cone and a
point light six, a cube's faces as six frusta (gfx has no cube textures,
and one atlas is one binding), 12 tiles at most a frame (two point lights,
or a point light and six spot lights). At most `maxLocal` lights cast a frame, in
the frame's order (the ones that matter most to the view); while their
tiles do not fit the square, they are halved; the others cast nothing that
frame. A tile is kept from the frame before while its light and what it
holds stay put (`cached`, and `light.shadow.cached`: Godot's and Unity's
cached shadows), so a level's lamps cost their shadows once. Their
filter is a 3x3 or a disc of 12 taps (`radius`, in the tile's texels),
their bias in metres a metre from the light (`localBias`, `bias`), and an
offset along the surface's normal (`normalBias`, in texels), both growing
with the distance as the tile's texels do.

tests/3d's `spotshadow` (two spot lights, a 3x3 and a disc), `pointshadow`
(a point light between pillars and two walls) and `shadowatlas` (six
lights, `maxLocal` 3, beside the sun's two cascades: the three that matter
most cast, a second frame keeps their tiles, a moved caster draws its
light's again) are its frames. Measured as above (two spot lights and a
point light over 25 posts, 33.6 ms unshadowed): their eight tiles drawn
each frame, 62.2 ms (1.85x); kept while nothing moves, 49.2 ms (1.46x: the
lookups alone). `Shadows` adds 115 KB natively (117 KB as wasm32),
`local` 46 KB more (43 KB): a program whose sun alone casts links none of
the local tiles.

### Sky and environment

`renderer.use(new Sky(device))` draws a sky behind the scene;
`renderer.use(Environment.fromImage(device, mime, bytes))` an
equirectangular image behind it that also lights it (image-based ambient
and reflections). The showroom puts the optional features together: an
environment map, normal maps, two shadow cascades, a morphing surface and
glass:

Example: [Showroom](/examples/showroom/Showroom.hx) (`helder run examples/showroom/Showroom.hx`).

#### Image-based light, prefiltered

`Environment.prefiltered(device, mime, bytes, levels)` lights the scene
from an atlas filtered once ahead (a tool: Expansion's `tools/envbake.py`):
`levels` rows of the sphere (equirectangular, width by width / 2) by
roughness (GGX's lobe convolved, the split sum's first half) and the
diffuse irradiance's row below them. The standard material reads two rows
by its roughness, blended, along the reflection, and the last along its
normal: 128 x 448 for 6 levels, 224 KB on the GPU, no mip levels.
[Indirect light](#indirect-light) prefilters an environment in helder itself,
at load, with light and reflection probes, area lights and lightmaps.

[examples/gltf-showcase](/examples/gltf-showcase) shows Khronos' sample
models (DamagedHelmet, FlightHelmet, SciFiHelmet, the extensions' tests)
under prefiltered HDR environments, compared with the sample viewer's
renders in its README (tens of MB of models: fetched when it plays):

Example: [glTF sample models](/examples/gltf-showcase/Showcase.hx) (`helder run examples/gltf-showcase/GltfShowcase.hx`).

## Indirect light

The light that does not come straight from a lamp: the sky's, what the
walls bounce, what a polished floor reflects. Each part below is opted in,
and a program that names none of them links none of it.

### An environment prefiltered by helder

`Environment.prefilter(device, width, height, texels, format)` takes an
equirectangular image (longitude across, latitude down; RGBA8 sRGB as an
image decodes, or linear `RGBA16F` or `RGBA32F` for an HDR sky) and
filters it once, at the first frame drawn with it, into the atlas
`Environment.prefiltered` reads: `levels` rows of the sphere by roughness
(GGX's lobe, the split sum's first half, by filtered importance samples)
and the diffuse irradiance's row, made from the image's spherical harmonics (`env.sh`,
projected on the CPU at load). Where the device has compute (WebGPU,
Metal, D3D11, GL ES 3.1) the atlas is written by a dispatch, elsewhere
(WebGL2) by a fragment pass: the same texels, one golden frame (tests/3d's
`sh`). The image itself is drawn behind the scene.
`Environment.prefilterImage(device, mime, bytes)` decodes one first.

Example: [An environment prefiltered by helder](/docs/examples/scene-environment/Sky.hx) (`helder run docs/examples/scene-environment/Sky.hx`).

`Environment.prefiltered` (an atlas filtered ahead by a tool) and
`Environment.fromImage` (a mip-mapped image read by roughness) still
work as before.

### Light probes

A `LightProbe` on a node is the light around a point as spherical
harmonics (`Sh`: nine RGB coefficients; `Sh.ofEquirect`, `ofFunction`,
`ofHemisphere`, `addDirectional`), reaching `radius`. A `ProbeGrid` is a
box of them on a regular grid, filled by code (`grid.fill(p -> ...)`) or
read from bytes baked once (`ProbeGrid.read`, `grid.write()`). With
`renderer.use(new Probes(device))`, each draw of the standard material
takes the light at its centre (a grid holding it, blended trilinearly on
the CPU, else its nearest probes), evaluated at its vertices: Unity's
per-object probes, nothing per pixel.

### Reflection probes

A `ReflectionProbe` on a node captures the scene from there once (six
faces into a cube, drawn by an offscreen twin of the renderer, then
prefiltered into its column of `Probes`' atlas) and is reflected by the
draws its box holds, parallax-corrected: a reflection is looked up where
it leaves the box, so a room's walls are reflected where they are. A draw
blends its two probes by how much of it each box holds (the box's walls
soft over `blend`), falling back to the environment. `probe.capture()`
captures it again; nothing is captured every frame.

Example: [Probes and area lights](/docs/examples/scene-probes/Room.hx) (`helder run docs/examples/scene-probes/Room.hx`).

The probes share one atlas (a column a probe, the environment's layout),
read by the probes variants alone; the environment stays its own, the
probes' fallback. Drawn with probes: the standard material's opaque draws, plain and instanced (pbr's
`probes` variants); normal-mapped, skinned and see-through draws, instanced
sets and materials of their own shader read the environment alone.

### Area lights

`Light.rectArea(color, intensity, width, height, range)` and
`Light.discArea(color, intensity, radius, range)` shine down their node's
-z from their front only, `color` times `intensity` their radiance
(three.js's units). With `renderer.use(new AreaLights(device))` the
standard material shades them with linearly transformed cosines (Heitz et
al.; three.js's tables, 64 KB): a rectangle's polygon, a disc as an
octagon of its area. Without it, and in other materials, an area light
is a point light at its centre. They take part in the frame's lights and
in `ClusteredLights` as their bounding sphere, and cast no shadows.

### Lightmaps

A `Lightmap` on a node is its baked light (the irradiance over pi, linear
`RGBA16F` or sRGB `RGBA8`) in its rectangle of a texture several nodes
share, read at the second uvs (glTF's TEXCOORD_1, a primitive's `uv1`).
With `renderer.use(new Lightmaps(device))` it replaces the ambient (mode
`Indirect`, the lights still added) or all the light (`All`). Nodes of one
mesh and material keep their own lightmaps (Bevy's model, not three's
`material.lightMap`); a lightmapped node is a draw of its own. Baking is a
tool's.

```haxe
var l = Lightmap.attach(node, new Lightmap(baked, new Vec4(0, 0, 0.5, 0.5), true));   // texture, rect (offset, scale), sRGB
l.mode = All;
renderer.use(new Lightmaps(device));
```

### Costs

Each part is a variant of the standard material compiled when a frame
first draws with it, so a frame without probes, area lights or lightmaps
compiles and draws as before. Per pixel: light probes cost nothing (their
light is evaluated at the vertices), a reflection probe two atlas reads
and a box intersection, an area light two polygons' integrals (four or
eight edges each) and two table reads. Per draw on the CPU: a probe
grid's eight probes blended, and each reflection probe's box tested. On
the GPU: the probes' atlas (`probes x size` by `(levels + 1) x size / 2`
RGBA16F texels: 8 x 64 by 7 x 32, 0.9 MB, by default), a capture's cube.

What each adds to a program (`tests/3d/size/sizes.sh`, the renderer's
level, Linux x86-64 and wasm32; unused, the whole phase adds 24 KB and 22
KB):

| | native | wasm32 |
|---|---|---|
| `Environment.prefilter` (Sh, the prefilter's pass and dispatch) | +144 KB | +143 KB |
| `Probes` (with the prefilter, the captures, two variants) | +300 KB | +333 KB |
| `AreaLights` (four variants, the 64 KB tables) | +295 KB | +352 KB |
| `Lightmaps` (one variant) | +71 KB | +96 KB |

## Fog

```haxe
var fog = new Fog(new Vec3(0.05, 0.07, 0.12), 0.03);   // colour (linear), density per metre
fog.start = 5;                       // metres clear before it
fog.falloff = 0.3; fog.height = 0;   // thinner upwards: valleys fill, hills and the sky above clear
fog.max = 0.9;                       // the most it hides
renderer.fog = fog;                  // null: none
glow.fog = false;                    // a material it does not cover
```

Exponential fog by distance, 1 - e^(-density * the distance past start),
with an optional height falloff (the density e^(-falloff (y - height))
times its own, summed along the view in closed form: Unreal's and
Quilez's exponential height fog), in linear light before tone mapping
(its colour times the exposure), so an HDR frame blooms and grades it
with the rest. It covers the standard material and the materials made
from it (`MaterialShader`), `Sky` and `Environment`'s background (as far
as the camera's far plane: uniform fog covers the sky, height fog clears
above), and fades `GpuParticles` and Additive materials (light added, not
turned to the fog's colour).

Here the fog's floor rises and falls (`fog.height`), the sky covered with
it; the sign at the end of the colonnade is a material the fog does not
cover:

Example: [Fog](/docs/examples/scene-fog/Fog.hx) (`helder run docs/examples/scene-fog/Fog.hx`).

## HDR and post-processing

An offscreen renderer made with `hdr` (`new Renderer(device, true,
samples, true)`; a `<Scene hdr>` box) draws in linear light into half-float
targets (RGBA16F: light brighter than white kept; the shaders' last step
`PbrShader.output` leaves the tone mapping to later), and a `PostProcess`
turns the frame into the 8-bit image shown:

Its effects (AO, depth of field, outlines, FXAA, a LUT: [Post effects
and the view buffers](#post-effects-and-the-view-buffers)) are fields of it, null by default.

```haxe
var post = new PostProcess(device);   // into RGBA8 targets (a <Scene>'s box's); (device, RGBA8, true): the frame
post.bloom = 0.05;                    // the share of the light spread: no threshold, what is bright blooms
post.toneMap = Aces;                  // Narkowicz's, the 8-bit path's; AgX; Clamp
post.saturation = 1.05; post.contrast = 1.05; post.lift = ...; post.gain = ...;
post.vignette = 0.3; post.grain = 0.03; // both 0 by default: no grain, a still dither
post.levels = 4; post.base = 2;       // a cheaper bloom: 4 levels from a quarter of the frame (default 6 from half)
renderer.post = post;                 // a <Scene hdr>'s box runs it; else post.run(enc, hdrColor, target, w, h, time)
```

Outside a `<Scene>`, the program draws into its HDR targets and runs the
chain into the frame itself (`renderer.drawInto`, then `post.run`). Tap
the example, or press Space, to switch the tone mapping: ACES, AgX, and
none (clipped at 1, what tone mapping saves):

Example: [HDR and post-processing](/docs/examples/scene-post/Post.hx) (`helder run docs/examples/scene-post/Post.hx`).

### Bloom

Bloom is the physically based kind (Jimenez, Call of Duty: Advanced
Warfare; Unity's HDRP): the frame filtered down a chain of half-sized
RGBA16F targets (13 taps, the first level in Karis' average against
fireflies) and back up (a tent filter, each level added to the one
above), mixed into the frame by its share. A run records 2 * levels
passes (6 levels by default) and allocates nothing; its targets are the
GPU's, as many as the levels, made again when the size, the base or the
levels change. On a phone 4 levels from a quarter of the frame (`base = 2`)
look alike at a third fewer passes and a quarter of the pixels.
`tests/3d/bloom.png` is its frame. A GPU that cannot draw into half floats
(GL ES without EXT_color_buffer_half_float or _float; WebGL2 enables
either): a `<Scene>` says so once and draws in 8 bits.

### Stages of your own

A program's own passes join the chain after the grade (`PostStage`), or
before the composite in linear light (`post.add(shader, bytes,
BeforeComposite)`: its image the scene's RGBA16F light, drawn into RGBA16F
targets, the last one's what depth of field, bloom and the composite
read; a blur of the program's own belongs there): a
shader drawn over the whole target, its vertex `{pos:Vec2}` (a triangle
in clip space, the chain's), its first texture the image so far (tone
mapped: a pixel art finish, a CRT, an outline), its first uniform block
the bytes given. Stages run in order, each reading the last one's image;
the last draws into the chain's output (the frame, or `run`'s target, of
any size: a frame drawn small and finished in big pixels on the screen),
the others into two RGBA8 targets of the run's size; the chain makes their
pipelines for what they draw into:

```haxe
var stage = post.add(FinishShader, finishBytes);   // fragment(i, p:{view:FinishView, frame:Texture2D})
stage.filter = Nearest;                            // read in big pixels (Linear by default)
stage.bind = enc -> enc.setTexture(slot, noise, sampler);  // anything else it reads
stage.enabled = false;                             // passed over; post.remove(stage)
stage.prepare = enc -> blurHalf(enc, post.source, post.width, post.height);  // its own passes first
```

While the chain runs, its context is the stages': `post.source` is the
scene's light it was given (linear, RGBA16F, its alpha the scene's
coverage) and `post.width`, `post.height` its size. A stage's `prepare`
is recorded before the chain's passes, outside any pass, every run
(enabled or not, so it may switch itself), for passes of its own from
that light: Little Skies' tilt-shift blurs it at half size there, then
mixes the blur in as its stage. A `<Scene hdr>`'s chain is there when its
`setup` is called, so stages are added there.

`tests/3d/poststage.png` is the bloom frame through two (a sepia grade,
then scanlines: tests/3d/StageShaders.hx). [examples/afterglow](/examples/afterglow)
finishes its whole frame as a painting this way.

## Post effects and the view buffers

```haxe
var post = new PostProcess(device);
post.ao = new Ssao({radius: 0.5, intensity: 1, samples: 8, halfRes: true});   // GTAO
post.dof = Dof.tiltShift({band: 0.2, falloff: 0.3, strength: 1});           // or Dof.focus({distance: 6, aperture: 0.02})
post.outline = new Outline({width: 2, color: new Vec4(1, 0.8, 0.2, 1)});     // group 1; outline.group(2, color, width)
Outline.select(node);                                                          // node and what is under it, group 1 (0: none)
post.antialias = Fxaa;                                                         // None | Fxaa
post.lut = Lut.fromImage(device, image);                                       // a 16 cubed strip (256 x 16); Lut.of(device, 16, grade)
post.ssr = new Ssr({maxDistance: 8, thickness: 0.25});                         // screen-space reflections
post.taa = new Taa();                                                          // temporal antialiasing; or post.smaa = new Smaa()
post.motionBlur = new MotionBlur({strength: 0.5});                             // the camera's; {objects: true} each object's too
post.godRays = new GodRays({intensity: 0.5});                                  // the sky's light streaming towards the sun
renderer.post = post;                                                          // the renderer draws what they read
```

The effects are a `PostProcess`'s fields, null by default: an effect a
program never sets is not linked (its class, its passes, its shaders,
and the view buffers if none reads them: `tests/3d/size/PostSize.hx`).
The order is fixed by what is right: AO in the lighting; in linear light
before bloom, reflections, then temporal antialiasing, then motion blur,
then depth of field; god rays added before the curve; the curve, the
grade, the LUT; FXAA or SMAA's blending in the composite's read of the
scene, the outline over everything. The
composite stays one pass: a variant compiled at build time with the
effects folded in (and one with FXAA), each effect off while its part of
the block is zero.

### The effects

- **The view buffers** (`ViewBuffers.of(renderer)`, a `RenderFeature`):
  a single-sampled prepass of the frame's opaque draws (pbr's prepass
  variants: the position, normal, roughness and alpha slots alone; a
  material of its own that replaces one of those gets its own prepass
  variants) into a sampled `Depth32F` depth and an `RGBA8` target of the
  view-space normal (octahedral, xy), roughness and metalness (z, four
  bits each) and the selection group (w). One pass of one colour target:
  gfx has no MRT. Their **motion** (`withVelocity()`, which TAA and motion
  blur by objects ask for themselves) is a second pass of the same draws
  into an `RGBA16F` target (`motion`): how far each pixel's point moved
  on the screen since the frame before, by each node's world matrix then
  and now (kept by node, nothing allocated) and the camera's
  view-projections, the jitter left out; an instanced run reads its last
  matrices from a buffer beside the renderer's, an instanced set moves
  with the camera alone, a skinned mesh is not drawn (what reads it takes
  the camera's motion from depth there). The main
  pass's multisampled depth is not theirs. AO, depth of field and the
  outline ask for them (`renderer.post` must be the chain: the renderer
  draws them); `scale` draws them at a share of the frame's size, by
  default half for AO and depth of field, whole with an outline. A
  program's own pass may read them (`depth`, `normals`,
  `inverseProjection`) in an `AfterPass` hook.
- **`Ssao`**: GTAO (Jimenez et al. 2016): slices of the hemisphere about
  the view (`slices`, 1 or 2), each's two horizons found in `samples`
  steps out to `radius` metres along whole texel steps (each tap a
  texel's centre on the slice), the visible arc integrated against the
  projected normal as a share of the slice's arc unoccluded (a plane is
  open whatever the slices: no stripes), at half the frame's size
  (`halfRes`), then blurred up to the view buffers' size by depth
  (bilateral), before the main pass. The standard material darkens its
  indirect light by it alone (the ambient, the environment's light and
  reflections), not the sun's or the lamps': a lit wall keeps its
  light. `intensity` is a power.
- **`Dof`**: a circle of confusion from the view buffers' depth, the
  scene's light gathered on a disc that wide (Vogel's, `samples` taps) at
  half the frame's size, a nearer tap taken only where its own circle
  reaches (a sharp foreground does not bleed), mixed in where the circle
  is wider than a texel. `Dof.focus({distance, aperture})`: a thin lens,
  sharp at the distance, its blur at infinity the aperture (a share of
  the frame's height), at most `radius`. `Dof.tiltShift({band, falloff,
  strength})`: a diorama's lens, sharp within `band` of the focus depth
  (a share of it), blurred past `falloff` more to `strength` times
  `radius`; its focus the depth under the frame at `center` (its v; the
  middle by default), or `distance`. A world's depth, not the screen's
  band: a far island inside the band is blurred.
- **`Outline`**: the selection is data, a group (1 to 255) on a node
  (`Outline.select(node, group)`, a component; its descendants take the
  nearest's), written by the prepass; the composite finds a group's edge
  within its width of a pixel (16 taps) and draws its colour over
  everything, see-through surfaces too. Each group has a colour and a
  width (`group(k, color, width)`); the view buffers are drawn whole.
- **`Fxaa`** (`post.antialias`): Lottes' FXAA 3 console pass, in the
  composite's read of the scene (its light read along the edge through
  the pixel, before the curve). A `<Scene>`'s MSAA stays the default:
  FXAA is for a box drawn with one sample (`antialias={false}`), or both.
- **`Ssr`** (desktop and web): each glossy pixel's reflected ray
  marched in view space (`steps` of `maxDistance` metres, the first
  dithered), a hit where it passes behind the view buffers' depth by less
  than `thickness`, refined by four halvings; at half the frame's size
  (`halfRes`), then mixed over the scene's light at the frame's size by
  Schlick's Fresnel (its F0 from the surface's metalness: the view buffers
  keep no base colour, a metal's reflection is untinted), the surface's
  gloss (none past `maxRoughness`) and the hit's confidence (faded at the
  screen's edges, with the distance, for rays towards the eye). Where
  nothing is hit the scene keeps its own (the environment's, the sky's).
  A linear march, not a hierarchical one: gfx's depth has no mip chain
  of its minimums yet.
- **`Taa`** (`post.taa`; desktop and web): the projection jittered by the
  next of 8 points of Halton's (2, 3) sequence each frame (to a
  sixteenth of a pixel: every rasterizer's grid, so edges match across
  back ends), the frame gathered with its history where its point was the
  frame before (the view buffers' motion, else the camera's from depth),
  the history kept within the pixel's 3 x 3 neighbourhood (YCoCg, its mean
  and spread inside their box: Salvi's variance clipping in Karis' clamp),
  in a tone mapped space (a bright speck weighs as a dim one), `blend` the
  new frame's share (0.1). The history is let go at a cut
  (`post.resetHistory()`), the first frame and a resize. The view buffers
  are drawn whole, with their motion.
- **`Smaa`** (`post.smaa`): Jimenez et al.'s morphological antialiasing,
  in three passes: the edges of the light's perceptual luma (local
  contrast adaptation: an edge beside one twice as strong is not one),
  then for each edge its run searched both ways (16 pixels) and the edges
  crossing its ends, the line a silhouette took through the staircase
  (MLAA's L, Z and U patterns; a crossing counted only where the edge
  steps on, not at a T) and the share of each pixel it covers, worked out
  rather than looked up; then the blending, in the composite. Its medium
  preset: no diagonal or corner patterns. It needs no view buffers.
- **`MotionBlur`**: McGuire et al.'s reconstruction in four passes: each
  texel's motion at the view buffers' size (the camera's from depth and
  the last view-projection, or with `objects` the view buffers' motion:
  a second geometry pass) times the shutter (`strength`: 0.5 a half-open
  one), at most `max` of the frame's height; the longest of each 8 x 8
  tile and of its neighbours; then each pixel gathers `samples` taps along
  its tile's line (every other one along its own motion when it moves at
  least half as fast: a turning wheel keeps its arcs), a tap counting
  where its motion reaches the pixel or the pixel's reaches it. A still
  background beside a moving object takes the object's smear.
- **`GodRays`**: from each pixel of a target a quarter of the frame's
  size, `samples` taps towards the sun's place on the screen, each the
  scene's light where the view buffers' depth is the sky's, weighted by
  its nearness to the sun (`falloff`) and fading by `decay`; added to the
  light before the curve (`intensity`). The sun is the world's first
  directional light (else the renderer's); behind the camera, none; faded
  as it leaves the screen (Mitchell, GPU Gems 3). Not volumetric fog.
- **`Lut`**: a 16 cubed (or 32) table as a 2D strip (gfx has no 3D
  textures: size slices of size by size side by side, red across, green
  down, blue by slice), read once in the composite after the grade,
  display values in and out: `Lut.fromImage(device, image)` (an
  identity strip graded in an image editor), `Lut.fromBytes(device,
  size, bytes)`, `Lut.of(device, size, (r, g, b) -> new Vec3(...))`;
  `strength` mixes it in.

## Instancing

### Batched nodes

Nodes drawing one primitive are one instanced draw whatever their scale
(uneven too: the normals are turned by the instance matrix's inverse
transpose), unless their material is see-through (`blend`) or skinned;
`renderer.instancing = false` draws each alone. The shadow maps batch
their casters the same way, a primitive's casters one instanced draw a
cascade (a skinned caster alone).

### InstancedMesh

For many copies without a node each, an `InstancedMesh` is one mesh drawn
from flat per-instance data in one instanced draw a primitive: a transform
(position, unit quaternion, uniform scale; or any affine matrix), a colour (times
the material's), and custom floats for a program's own shader:

```haxe
var rocks = new InstancedMesh(Shapes.box(device, rock), 100000);   // capacity, count, custom floats
InstancedMesh.attach(world.node("belt"), rocks);                  // drawn while the node is shown
rocks.bounds = beltBounds;                                        // optional: culled whole, fitted by Shadows
// each frame, nothing allocated:
for (i in 0...rocks.count) rocks.setTransform(i, x, y, z, qx, qy, qz, qw, scale);
rocks.setColor(i, new Vec3(r, g, b));
```

The data is the instance buffer's layout (`data`, 64 bytes an instance;
`customData` beside it, uploaded to `customBuffer`), uploaded by the
renderer before its pass when written (count instances, one
`writeBuffer`); the standard material draws it (normal maps too), and it
casts into `Shadows`' map. In markup: `<instances of={rocks}/>`.

The asteroid belt draws its rocks three ways (its buttons): as nodes one
by one, as nodes batched by the renderer, and as one `InstancedMesh` of
up to 200,000; the overlay counts the draws. Its InstancedMesh, made once
and written each frame:

Example: [Instancing stress](/examples/instancing/Instancing.hx) (`helder run examples/instancing/Instancing.hx`).

Tests: `src/helder/scene/render/InstancedMesh.test.hx` (the layout, resize,
nothing allocated), the 3d lane's `instancedmesh` frame (shadows, a set
culled), `tests/3d-ui/SceneUiCheck.hx`.

### Occlusion culling

```haxe
renderer.use(new Occlusion(device));        // gfx's occlusion queries (1024 by default)
Occlusion.test(building);                   // its meshes culled while hidden; untest(node)
renderer.occluded;                          // the last frame's primitives not drawn
```

Each tested node's bounds are drawn as a box after the frame's opaque
surfaces, depth tested and not written, inside an occlusion query of
gfx's (`Device.createQueries`; `Encoder.beginQuery`, `endQuery`; GL ES
3.0's and WebGL2's `ANY_SAMPLES_PASSED`, WebGPU's occlusion query sets,
Metal's visibility results, D3D11's occlusion queries). A node whose last
answered query passed no sample is culled at the next frames' extraction
(Babylon's occlusion queries: a frame or more late, never waited for);
its box is still drawn each frame, so it comes back when it is seen
again. A node outside the view, or whose bounds hold the eye, is not
tested and never culled, its last answer let go (`Device.resetQuery`).
Each box is a draw of its own (a query each): test what a wall may hide
(a building, a room's contents), not every pebble. GPU-driven culling
against a depth pyramid is the compute tier's.

What a frame costs in draw calls, by pass, to measure the next
optimisation against:

| Pass | The last frame's, this renderer | Every renderer's, summed |
|---|---|---|
| main (the scene's colour pass) | `renderer.draws` (and `instanced`, `culled`, `occluded`) | `FrameCounts.sceneDraws` (and `occluded`) |
| shadow maps (every cascade) | `renderer.shadowDraws` (`Shadows.draws`) | `FrameCounts.shadowDraws` |
| the view buffers' prepass (`ViewBuffers`: the opaque draws again, single-sampled) | `renderer.prepassDraws` | `FrameCounts.prepassDraws` |
| post (AO's and depth of field's passes, bloom down and up, the composite, stages) | `renderer.post.draws` | `FrameCounts.postDraws` |
| everything the GPU was given (the UI's too) | | `FrameCounts.draws`, `passes`, `instances` |

### Sprites

Quads that face the camera (three's `Sprite`, Godot's billboard modes), as
one `InstancedMesh` of a material: clouds, halos, trees far off.

```haxe
var trees = new Sprites(device, Material.unlit({texture: atlas, alphaCutoff: 0.5}), 64, {mode: Axis, columns: 2, rows: 1});
Sprites.attach(world.node("trees"), trees);
trees.count = n;
for (i in 0...n) trees.set(i, x[i], h[i] / 2, z[i], h[i] * 0.7, h[i], 0, i % 2);   // position, size, rotation, atlas cell
trees.setColor(i, new Vec3(r, g, b));
```

`mode` is `Spherical` (facing the camera, turned on the screen by a
sprite's rotation), `Axis` (turning about `axis` alone: upright along it)
or `Fixed` (facing +z). Each sprite is a position in the world, a width and
a height, a rotation, an atlas cell (`columns` by `rows` of the material's
texture, left to right then down: the material's `uvScale` set to a
cell's share, the cell in the instance matrix's last w, which the
instanced variants read: `PbrShader.instanceUv`) and a colour. The
renderer turns them before its pass (`InstancedMesh.prepare(viewProj)`:
the camera's axes from its view-projection), only when the camera or a
sprite changed; see-through ones are drawn after the opaque surfaces with
the see-through instanced sets (an `Additive` halo), `Alpha`'s sorted far
to near among themselves. Nothing is allocated a frame. In markup:
`<sprites of={trees} mode="axis"/>`. Tests:
`src/helder/scene/render/Sprites.test.hx` (the turn, the atlas, the
sorting, nothing allocated, natively and as wasm32-wasi), the 3d lane's
`sprites` frame (trees on an axis, clouds sorted, additive halos).

## Levels of detail

### Lod

A `Lod` on a node lists its meshes from the finest to the coarsest, each
drawn while the node covers at least its `until` of the view's height:
the share its bounds' sphere covers (Babylon's screen coverage), the same
at any field of view or resolution. The last level's `until` is 0 by
default (drawn however far); past a last `until` above 0 nothing is drawn.
A level holds within a band of `hysteresis` about its threshold (0.1: 5%
each way), so a node at the edge does not flicker between two:

```haxe
Lod.attach(world.node("tree"), [{mesh: hi, until: 0.15}, {mesh: mid, until: 0.04}, {mesh: lo}]);
```

The renderer picks the level as it extracts the frame's draws, so nodes
of one level and material are still one instanced draw. `lod.level` and
`lod.coverage` are the last frame's; `Lod.coverageOf(viewProj, x, y, z,
radius)` and `lod.choose(coverage)` are the pick itself. A program that
never attaches a `Lod` links none of it (the renderer reaches it through
`Lod.pick`, set by `attach`).

`Lod.range(node, begin, end)` is a visible range (Godot's
`visibility_range`): the node and what is under it drawn only while the
camera is `begin` to `end` metres from it, a cluster of nodes swapped
for one far off (HLOD).

In markup: `<lod levels={levels} hysteresis={0.1} end={80}/>`.

### Instances culled and levelled

An `InstancedMesh` is drawn whole by default, culled only by its set's
`bounds`. With `renderer.use(new InstanceCulling(device))` its instances
are tested against the view one by one (their mesh's bounds' sphere
through each one's matrix), and each kept one drawn at its level of the
set's `levels` (Lod's thresholds), so a forest of thousands draws the few
hundred in view, the far ones coarse:

Example: [Levels of detail](/docs/examples/scene-lod/Levels.hx) (`helder run docs/examples/scene-lod/Levels.hx`).

Where the device has compute and indirect draws (WebGPU, Metal, D3D11,
GL ES 3.1) it runs on the GPU: a dispatch a set, each kept instance's
matrix appended to its level's part of a buffer the draws read as their
instances, their counts into indirect draws' arguments, nothing read back.
Elsewhere (WebGL2) the same test runs on the CPU and the kept matrices
are uploaded by level. Both draw the same frame (tests/3d's `lod` frame,
drawn by both against one golden). A set it does not take is drawn whole:
one with custom data (its second buffer is not culled with it), a
see-through one (its order is its own: `Sprites`), more than four levels
or four primitives a level. Shadows draw every instance at the set's mesh.

Measured (`tests/bench/LightBench.hx`, as [Lights and
shadows](#many-lights)): a field of 20,000 spheres of three
levels, 678 of them in view, drawn whole 438 ms a frame; culled and
levelled on the GPU 42.4 ms (0.1x), on the CPU 41.3 ms. `InstanceCulling`
adds 52 KB natively (50 KB as wasm32), `Lod` 42 KB (28 KB), nothing when
unused.

Not built: `Pack --lod` (meshes simplified at build time), a dithered
crossfade between levels, and occlusion culling (phase 7).

## GPU particles

```haxe
var fx = new GpuParticles(device, 32768);   // a ring of 32,768: the oldest written over when full
fx.gravity = new Vec3(0, -4, 0);
fx.drag = 0.4;                              // per second
renderer.use(fx);
// each frame:
fx.advance(dt);
fx.emit(x, y, z, vx, vy, vz,   // where, how fast (units a second)
	r, g, b, a,                // linear colour (above 1: brighter than white), opacity
	size0, size1, life,        // half its side at birth and at death, seconds
	stretch, heat);            // drawn as a streak of that many seconds; whiter while young (0 to 1)
```

`GpuParticles` (`renderer.use(new GpuParticles(device, capacity))`) writes
a particle once, when it is emitted, into a ring of `capacity` particles,
and `GpuParticleShader` moves it from then on, from the feature's clock
(`time`, which the program sets or `advance` moves): its start, its
velocity slowed by `drag`, `gravity`. Nothing is simulated or allocated a
frame: the frame uploads only the particles emitted since the last (one or
two runs of the ring) and draws the ring in one instanced draw at
`AfterOpaque`, added to the scene. `fx.live` bounds the newest slots drawn
(the emission rate times the longest life): a program emitting less than
its ring holds draws less. For sparks, debris, exhaust trails, smoke and
flashes. Tap the example for a burst:

Example: [GPU particles](/docs/examples/scene-particles/Sparks.hx) (`helder run docs/examples/scene-particles/Sparks.hx`).

## Lines

```haxe
renderer.use(new LineRenderer(device));
var path = Lines.attach(world.node("aim"), new Lines(512, {width: 6, join: Round, cap: Round, dash: 0.2, gap: 0.15}));
// each frame: nothing allocated
path.count = n;
for (i in 0...n) path.setPoint(i, xs[i], ys[i], zs[i], 1, 1, 1, fade(i));
path.dashOffset = -time;     // the dashes march along it
```

`Lines` are a polyline through their points, or separate segments
(`segments: true`, a pair of points each), drawn by a `LineRenderer` (a
`RenderFeature`) as quads on the screen: gfx's `Lines` topology is one
pixel wide, and WebGL ignores a line's width, so a width here is the
same on every back end (three's `Line2` and `LineMaterial`, Babylon's
GreasedLine). A point is a position in its node's frame and a colour
(linear rgb and alpha, blended along a segment). The program writes them
into the line's flat data, as an `InstancedMesh` takes its instances:
nothing is allocated a frame, and the renderer uploads the points once
they changed.

- **`width`** in pixels (`widthUnits: Pixels`, the default), or in the
  world's units (`World`: thinner far off, as geometry is).
- **`join`**, where segments meet: `Miter` (bevelled past four half
  widths out), `Round` or `Bevel`; **`cap`**, the line's ends: `Butt`,
  `Round` or `Square`; `closed` joins the last point back to the first.
- **`dash`** and **`gap`**: a dashed line, lengths in the line's own
  units along it, `dashOffset` moving them (a marching line).
- **`overlay`**: drawn over everything, after the scene, not depth tested;
  else depth tested and written. **`transparent`**: blended by the
  colours' alpha, after the see-through surfaces (not written to depth);
  an opaque line ignores alpha.
- **`toneMapped: false`**: its colours as they are into an 8-bit target
  (a debug colour's pure red), not tone mapped. Lines are fogged.

Each line is one instanced draw of a segment an instance: a quad across
the segment and a fan of eight triangles at each end (the start's cap,
the end's join with the next segment or cap), placed in pixels by the
vertex stage from four views of one point buffer (the point before, the
segment's two, the point after). A segment crossing the near plane is
cut at it.

Example: [Lines](/docs/examples/scene-lines/LinesDemo.hx) (`helder run docs/examples/scene-lines/LinesDemo.hx`).

A program drawing lines links the `LineRenderer` and its shader: 64 KB
natively, 80 KB as wasm32 (`tests/3d/size/sizes.sh`); one that never
makes one, nothing.

In markup a line is `<lines of={path}/>` ([`<Scene>` markup](/src/helder/scene/view/README.md):

## Text in the world

```haxe
var font = FontFile.parse(Asset.embed("fonts/Inter.ttf"));
var label = Text3D.attach(world.node("score"), new Text3D(device, font, "0", {size: 0.3, billboard: true}));
label.text = Std.string(score);   // its glyphs made again: a change, not a frame

var word = Geometry.text(font, "helder", {size: 1, depth: 0.2, bevelSize: 0.02});   // a VertexData
var badge = Geometry.extrude(path, {depth: 0.1});   // any helder.canvas Path, holes and all
```

### Extruded shapes and text

`Geometry.extrude(path, options)` makes a solid of a `helder.canvas`
`Path` (three's `ExtrudeGeometry`): the path made polygonal and simple
by canvas' boolean ops first (`PathOps.simplify`: curves flattened within
`tolerance`, overlaps merged, holes found by the fill rule, `evenOdd` or
non-zero), so an SVG icon, a union of shapes or a glyph run is one
shape; its caps cut into triangles (ear clipping, holes bridged in) and
its sides walled, from z 0 (the back, facing -z) to `depth` (the front,
facing +z). A `bevelSize` rounds the caps' edges inwards over
`bevelSegments` steps of a quarter circle; the sides are smooth along a
curve, sharp where the outline turns by more than 30 degrees. `depth: 0`
is the front alone, a flat shape.

`Geometry.text(font, text, options)` is a text's outlines made so
(three's `TextGeometry`): helder.text lays it out (`size` the em's height
in the scene's units, `lineHeight`, `letterSpacing`, lines aligned by
`align`: 0 left, 0.5 centred, 1 right), helder.canvas gives each glyph's
curves (`Glyphs`), and they are extruded as above, the first baseline at
y 0. Both are linked only by a program that calls them.

### Text3D

`Text3D` is text that belongs to the world (Godot's `Label3D` and
`TextMesh`): a component drawing `Geometry.text`'s geometry in one
instanced draw, sized in the scene's units, centred on its node, depth
tested, fogged, sorted and shadowed like any mesh, sharp at any
distance. Unlit by default (its `color` as given); `lit: true` makes it a
Lambert material, `material` any of the program's. `billboard` turns it
to the camera each frame, its node's position and scale kept. Setting
`text` makes its glyphs again. Rays hit its triangles
([Picking](#picking)). `<Ui>` stays for text that is ui (layout,
wrapping, input) over the scene.

Example: [Text in the world](/docs/examples/scene-text/TextDemo.hx) (`helder run docs/examples/scene-text/TextDemo.hx`).

It costs what it links (`tests/3d/size/sizes.sh`): 647 KB natively, 701
KB as wasm32, most of it helder.text's layout and font reading, canvas'
boolean ops and the unlit material's shaders; a program that already
draws text or uses `Material.unlit` pays less.

In markup: `<text3d font={face} text={score} size={0.3} billboard/>`, or
`of={label}` for one made in code ([`<Scene>` markup](/src/helder/scene/view/README.md)).

Tests: `src/helder/scene/render/Extrude.test.hx` (a square's and a ring's
solids closed and facing out, a circle's caps' area, a bevel's inset
caps, the triangulator with two holes, a text's glyphs flat, solid,
aligned and on two lines); the 3d lane's `text3d` frame (a word extruded,
bevelled, lit and shadowed, a label turned to the camera, two lines
aligned right; its probe casts rays at the word's glyphs, the word made
shorter, fewer hit).

## Picking

```haxe
final hit = new Hit();                                   // the program's, refilled by each cast
var ray = camera.ray(x, y, aspect);
if (world.raycast(ray.origin, ray.dir, hit)) paint(hit.node, hit.uv);

final hits = new HitList(), through = new RaycastOptions({maxDistance: 50, layers: 2, backfaces: true});
world.raycastAll(origin, dir, hits, through);            // every triangle crossed, nearest first
```

`world.raycast(origin, dir, hit, ?options)` casts a ray at a world's
triangles (three's `Raycaster`, Bevy's `MeshRayCast`): each shown node
drawing a mesh, and each instance of an instanced set (`InstancedMesh`,
`Sprites`, `Text3D`), the ray brought into its frame (turned, moved,
scaled unevenly too), its bounds first, then each primitive's bounds and
its triangles. The nearest hit fills a `Hit` the program owns: the
node, the distance (the world's units), the point, the normal there (its
vertices' normals blended, in the world, turned towards the ray), which
side was hit (`front`), the primitive, its `triangle`, the barycentric
weights of its corners, the `uv` there and the `instance` (-1 for a
node's mesh). `raycastAll` refills a `HitList` with every triangle
crossed. Nothing is allocated a cast.

`RaycastOptions` (kept, not made a cast): `maxDistance`, `layers` (a
mask; a node's are 1 unless `Raycaster.setLayers(node, mask)`),
`triangles: false` (the primitives' bounds alone, `Pick.ray`'s way),
`backfaces` and `instances`. `Pick.ray(world, origin, dir)` stays the
bounds-only path.

### Trees

Each primitive's triangles are searched through a `Bvh` (three-mesh-bvh's
MeshBVH): a flat array of nodes, each a box and two children or a leaf of
at most 8 triangles, built by the surface area heuristic over 12 bins a
split, the triangles' corners copied in its order beside it. A primitive
keeps its data on the CPU for it (`Primitive.data`: the bytes the GPU was
given; `Mesh.keepCpu = false` lets them go, and its casts are by bounds)
and builds its tree when first cast at; `Shapes.cpu(geometry, material)`
is a mesh of data alone, cast at but not drawn (a level's collision
shapes, tests). The asset step packs the trees with a model
(`helder.scene.gltf.Pack --bvh`: read as they are, so a level loads
pickable). A tree is a cast's alone (its stack is its own: one cast at a
time). Skinned and morphed meshes are cast at in their rest pose;
`bvh.refit(vertices, stride, data)` fits a tree to moved vertices.

Raycasting costs a program that casts 55 KB natively, 53 KB as wasm32
(`tests/3d/size/sizes.sh`: the raycaster, the tree's build and casts).

### In a `<Scene>`

`<Scene pick="triangles">` picks the pointers' nodes by their triangles,
and `SceneEvent` gains the triangle's `normal` and `uv`, a drag that
stays on its node updating them: painting on a model, placing on a
surface. `pick="bounds"` (the default) picks by the meshes' boxes. The
choice is made when compiling, so a box picking by bounds links no
raycaster.

Example: [Picking](/examples/picking/Picking.hx) (`helder run examples/picking/Picking.hx`).

Tests: `src/helder/scene/render/Bvh.test.hx` (against brute force on
random rays at a torus knot, a soup of crossing triangles and a flat grid:
the same nearest triangle at the same distance, every triangle by
`intersectAll`; its leaves; packed equal to built; backs; refit; nothing
allocated a cast), `Raycaster.test.hx` (turned and unevenly scaled nodes,
the nearest of several, children, hidden nodes and layers, bounds alone,
backs, instances, every hit in order, nothing allocated a cast),
`tests/3d-ui/SurfaceCheck.hx` (a click on a box's face in a `<Scene
pick="triangles">`: its uv and normal), the 3d lane's `packed` frame (the
sample packed with `--bvh`: each tree the one built from its data) and
`text3d` frame (rays at a word's glyphs), `tests/typescript/helder/picking.ts`
(from TypeScript, without a GPU).

## Input

```haxe
var actions = new InputMap();
actions.bind("jump", Key(0x20)).bind("jump", Region(0.75, 0.5, 1, 1));   // Space, or the screen's lower right
actions.bind("moveX", KeyAxis(0xFF51, 0xFF53));                         // the arrows
App.run(frame, e -> actions.event(e));
// each simulation step:
actions.step();
if (actions.pressed("jump")) ...;
var x = actions.axis("moveX");
```

Actions are named once and bound to keys, pads and the screen; gameplay
reads the actions, not the devices. The walker's arrow keys, WASD, a
gamepad's stick and the screen's lower right corner are its actions:

Example: [Walker](/examples/walker/Walker.hx) (`helder run examples/walker/Walker.hx`).

### On-screen controls

Fingers are actions too, through on-screen controls that are virtual
devices (Unity's on-screen controls): gameplay reads the same actions as
for keys and pads.

```haxe
final move = new VirtualStick({zone: Zone.rect(0, 0.4, 0.5, 1), radius: 60, deadZone: 0.1});   // floating: where the thumb lands
final fire = new VirtualButton({zone: Zone.circle(0.88, 0.8, 40)});                            // radius in points
actions.bind("moveX", Stick(move, 0)).bind("moveX", KeyAxis(0x61, 0x64)).bind("moveX", PadAxis(0, 1));
actions.bind("lookX", TouchDelta(0, Zone.rect(0.5, 0, 1, 1), 0.3)).bind("lookX", PadAxis(2, 1));
actions.bind("fire", Button(fire)).bind("fire", PadButton(7)).bind("grab", Touch(Zone.rect(0, 0, 0.5, 0.4)));
// in the ui, over the scene: the stick drawn where the thumb holds it
<Stick bind={move} left={24} bottom={24}/>
```

`step` reads `helder.os.Pointers` (no events needed): each finger's press
is taken by the first control whose zone it began in (sticks, buttons and
`Touch` zones, then `TouchDelta`'s look zones), if nobody had it: not a
press on a ui node (helder.ui's window marks those the ui's, so a touch
on a HUD button never reaches the game), and kept until it lifts or is
cancelled, wherever it goes (a finger sliding over a button from
elsewhere does not press it; a button's finger sliding off lets it go).
A cancel lets go too: the player stops. `TouchDelta` is the drag over
the step in points times its scale (a look, not clamped); a press and
its release within a step still count. Equal zones are one control.
Nothing is allocated per event or per step (`changed`'s closures and the
key sets' maps are gone). Tests: `src/helder/scene/input/TouchActions.test.hx`
(natively and as wasm32-wasi, the allocation included),
`tests/3d/InputCheck.hx`, `<Stick>` drawn in `tests/3d-ui/SurfaceCheck.hx`.

## Debugging

`FrameStats` keeps the last frames' times (and, given to `add`, the CPU's
share of each), the renderer's counts, `percentile(0.5)`, `percentile(0.99,
true)` and `fps()` without allocating; `Overlay` draws them over the frame
with `helder.ui`'s drawn renderer (put `src` on the class path where it is
used): its bars and figures, with `detail` the fps, frame time and CPU
p50/p99 and the program's own `lines`, and with `extra` a program's own
controls in its pass (`text` in its pixel font, `rect`; `panel = false`:
those alone).

The performance examples use it: [Instancing](#instancing)'s asteroid
belt, [GPU particles](#gpu-particles)' galaxy,
[examples/bunnymark](/examples/bunnymark) and
[examples/physics-stress](/examples/physics-stress). What a frame costs
in draw calls, by pass: [Instancing](#draw-calls-by-pass).

### Debug drawing

```haxe
renderer.use(new DebugDraw());
// anywhere, each frame (a script, the physics step): gone the next frame
Debug.line(a, b, 0xFF4040);
Debug.ray(origin, velocity, 0.5);
Debug.aabb(mesh.bounds);
Debug.sphere(target, 2);
Debug.overlay(true);  Debug.axes(player.worldMatrix(), 0.5);  Debug.overlay(false);
```

`Debug`'s calls draw lines for one frame from anywhere (Bevy's gizmos):
nothing to keep or remove, and nothing allocated, written into a ring of
segments that the `DebugDraw` feature draws through a `LineRenderer`
([Lines](#lines)), one draw depth tested and one over everything
(`Debug.overlay`), then clears. A colour is `0xRRGGBB` as written, not lit,
fogged or tone mapped. The calls: `line`, `ray` (an arrow's head at its
end), `arrow`, `aabb`, `boxOf(matrix, min, max)` (a turned box: a node's
bounds), `sphere`, `circle`, `cross3`, `axes(matrix, size)`, `grid`,
`frustum(camera, aspect)`, `light(node)` (a directional light's arrows, a
point light's range, a spot's cone), `skeleton(skin)` and `path(curve,
n)`.

**Compiled out of a release.** `Debug`'s calls are macros: in a release
build (`helder build`'s `-D helder.release`) they are nothing, their
arguments not computed either, unless `-D helder.debugdraw`. `DebugDraw`'s
own functions of the same names are always there (TypeScript calls
those). The ring holds `DebugDraw.capacity` segments a frame (16,384; set
before the first call), calls past it dropped and counted (`dropped`).

### Helpers

Helpers are components of a node that make those calls for it each frame
(three's helpers): `AxesHelper.attach(node, size)`,
`BoundsHelper.attach(node)` (its mesh's box, turned with it),
`LightHelper.attach(node)`, `CameraHelper.attach(node)` (its camera's view
volume), `SkeletonHelper.attach(node)` (its skin's bones), and
`GridHelper.attach(node, {size, divisions})`: an infinite grid on the
node's plane, a shader, not lines (each line a pixel wide however far, a
major line every tenth, the axes red and blue, fading out at `fade`).
Unlike `Debug`'s calls they stay in a release: a program attaching one
wants it. In markup: `<axesHelper size={1}/>`, `<gridHelper size={10}/>`,
`<boundsHelper/>` in a mesh, `<lightHelper/>` in a light ([`<Scene>`
markup](/src/helder/scene/view/README.md)), their box given a `DebugDraw`.

What it costs a program that uses it (`tests/3d/size/sizes.sh`):
`DebugDraw` with its calls and the line helpers, 82 KB natively and 99 KB
as wasm32 (the lines' renderer with it); `GridHelper` 21 KB more; `Debug`'s
calls in a release, nothing.

Example: [Debug drawing](/docs/examples/scene-debug/DebugDemo.hx) (`helder run docs/examples/scene-debug/DebugDemo.hx`).

Tests: `src/helder/scene/render/DebugDraw.test.hx` (each call's segments,
a colour as written, the ring's capacity, nothing allocated); the 3d
lane's `debugdraw` frame (each call, a frame allocating nothing) and
`helpers` frame (each helper, the grid under them).

### Headless

`helder run <entry> --headless` runs a program offscreen on a virtual
clock: `--snap out.png --at 2` writes its frame at two seconds, `--stats
out.json` every frame's times and counts (the draws by pass). The 3d
lane's frames and the examples' videos on the site are made this way.

### A material of its own

A material of its own is `material(pbr.with({...}))`, as Haxe's
MaterialShader.material: `pbr` is the standard material's slot object
(src/helder/scene/pbr.ts: PbrShader.hx in TypeScript, keep the two in
step; tests/typescript/definitions/pbr.ts checks their text is the same;
its uniform blocks' arrays, PbrProbes' harmonics, are helder/gfx's
`UniformArray<Vec4, 7>`, Haxe's `@:length(7)`),
and its value's `apply(material, {glow: bytes})` gives a material the
shader and its blocks (`params.glow.write(value, bytes)`):

```ts
type GlowParams = {color: Vec4, time: Vec4}
const Glow = material(pbr.with({
  emissive: (s: PbrSurface, p: {glow: GlowParams}): Vec3 => p.glow.color.xyz.mul(0.6 + 0.4 * sin(p.glow.time.x * 3 + s.world.x))
}))
Glow.apply(orb, {glow: bytes})
```

The shading models are `helder/scene`'s too: `lambert`, `toon`, `phong`,
`unlit`, `matcap`, `normals` and `depth` (src/helder/scene/shading.ts,
helder.scene.render.shading's in TypeScript, checked the same text by
tests/typescript/definitions/shading.ts), so `material(toon.with({...}))`

factories, `Geometry`, `Curve3`, `Sprites` and `Light.hemisphere` are the
generated declarations' (`LightKind`, `SpriteMode` and `Blend` their
enums' values by name). A slot of several inputs is typed as its default:
`direct: (s: LitSurface, l: LightSample, p: {...}) => Vec3`. The 3d lane
